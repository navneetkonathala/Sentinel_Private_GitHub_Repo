Sentinel, explained simply

This guide is for learning the project from the beginning. You do not need to know machine learning first. Sentinel watches a sequence of numbers and points out readings that look very different from recent readings.

First: what is an anomaly?

A time series is a list of measurements in time order. For example, a machine might report its temperature once every second:

40.1°, 40.4°, 39.9°, 40.2°, 58.0°, 40.3°

If the machine usually stays near 40°, the 58° reading is unusual. Sentinel calls that reading an anomaly.

What this project detects: unusual numeric measurements. It does not inspect internet packets or decide whether a server is under attack. Temperature, response time, memory use, or another numeric signal could be supplied, but the demo currently makes its own sample numbers.

How the permitted detector works

The challenge explicitly permits sliding-window adaptive thresholds. Sentinel uses a robust version: a rolling median and MAD set the threshold from recent clean readings. We chose this as a lightweight, explainable fit for a streaming demo. We have not benchmarked it against the official NAB data, so we cannot claim it is the best-performing method yet.

  1. Remember recent readings. A queue called values keeps up to 51 accepted numbers.
  2. Wait to learn. It collects 12 readings before it starts judging new ones.
  3. Find the usual middle. The median is the middle number after sorting. One giant spike does not pull it around like it can pull an average.
  4. Measure usual variation. MAD is the median distance of the readings from that middle.
  5. Check the new number. A robust score measures how far it is from normal. If its absolute score is above 3.5, Sentinel marks it as an anomaly.
  6. Learn from normal readings. A flagged reading is not added to the history, so one spike does not immediately become the new normal.
center = median(recent_readings)
mad = median(distance_from_center)
score = (new_reading - center) / (1.4826 * mad)

if abs(score) > 3.5:
    status = "anomaly"

The value 1.4826 adjusts MAD to a familiar spread scale for data that is roughly bell-shaped. The tiny floor in the code prevents dividing by zero when recent values are almost identical.

What does sentinel.update(value) give back?

For each new number, it returns a small dictionary: the reading, status (warming_up, normal, or anomaly), direction, difference from the baseline, robust score, baseline, upper and lower limits, and a plain-language explanation. During warm-up, it also tells you how many readings it has collected and how many it still needs.

from sentinel import Sentinel

detector = Sentinel()
result = detector.update(58.0)
print(result["status"])

In a real program, the input would come from a sensor or service that sends timestamped measurements. This repository does not yet connect such a source.

What the website is showing

  • The green line is the demo's generated signal.
  • The dark dashed line is its estimate of the usual level.
  • The pale dashed lines show the allowed range.
  • An orange dot is a reading outside that range.
  • Inject anomaly adds one sudden high or low reading. Simulate drift gradually moves the readings.

Nearby flagged readings are grouped into one event in the web log. Each event shows its start time, approximate duration, number of flagged samples, peak reading, expected range, robust score, and a sentence saying how far the peak crossed the limit.

Important: the web demo uses JavaScript to simulate this behavior. It does not run sentinel.py, load the official NAB dataset, or provide measured benchmark results. Its event duration is estimated from the demo's roughly 0.9-second sample interval.

What is still needed for a real result?

The challenge brief names a prepared NAB dataset and asks for evaluation against labeled anomaly periods. That data is not in this project folder. To claim performance, the team still needs the provided dataset, a data loader, and measurements such as event F1, precision, recall, detection delay, and runtime.

For now, present Sentinel as a learning prototype and use the buttons to explain the idea. The demo can show how an anomaly detector behaves, but it cannot prove how well it performs on real server or sensor data.
